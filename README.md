# diamondrun
## 概要
Minecraftにて、複数人で一定時間内に掘れたダイヤモンドの数で競う対戦システムのデータパック。

## ゲームルール
【ゲームの流れ】
1. ゲーム開始
2. 準備時間：5分
3. 対戦時間：30分間
4. クールタイム/結果発表：1分間
5. 3.4.を最後の1人になるまで続ける
ラウンド制で戦うサバイバル形式。各ラウンドでダイヤモンドを獲得した数が1番少なかった人が脱落。
各ラウンドは最小限のクールタイムを挟み矢継ぎ早に行われるため、時間管理も戦略の1つ。

## 初期配布
* ダイヤモンドのツルハシ：幸運5, 耐久力3, 効率強化5
* 鉄のレギンス：スニーク上昇1, 耐久力3
* エリトラ
* ロケット花火 64：飛翔時間1
* 金のニンジン 128

## 対応バージョン
Java 1.21.4

## プレイ人数
2人〜5人

## 遊び方
遊びたいワールドを作成後、ワールドデータ内のdatapacksフォルダ内に本ファイルをコピーしてください。\
その後下記のコマンドを打ち込んでいただくとセットが現れます。各自プレイヤーがエントリーを済ませた後、STARTを押すとゲームが始まります。\
`/function diamondrun:set/set`\
また上記のコマンドで上手くいかない場合は一度下記のコマンドを打ち、データパックを読み込み直してください。\
`/reload`

## データパック制作について
【期間】\
データパック勉強期間（準備期間）：2日 \
本データパック制作期間：3日

鉄千用データパック https://minecraft-mcworld.com/101274/ \
を使用したことがある人が直感的に使いやすいようにセット周りは雰囲気を寄せて構築した。\
また初めてのデータパック制作だったため、ディレクトリの構成や命名規則などを参考にしつつ、可読性が上がることを意識して制作した。

## 課題点
【本データパックに関する課題】
* セット周りのUI/UXがこのゲーム用に最適化されていなかった
→ セット周りを鉄千データパックに寄せて構築したがこのゲームではセットに帰ってくる必要がないため、エントリーの仕組みはもっと一般化出来た またエントリーボタンを区別しなくていいため参加可能人数も5人以上にすることが出来た
* `/function/system/count/diamond.mcfunction` にてゲーム内で直接functionを読むと上手くスコアが反映されるのにゲームの流れの中だとスコアが反映されない問題を解決できなかった
* タイマーのスコアの減少に関する構築を `main.mcfunction` で行ったため、ループを止める処理が複雑になってしまい時間が足りなくなってしまった
→ タイマーのスコアの減少は再帰処理にすれば `main.mcfunction` への記述は最小限で済んだのではないだろうか
* ゲーム終了のシステムが間に合わず構築できなかった ゲームの残り人数スコアである remain を作成していたので remain が1のときにゲームが終わるように構築するつもりだった

【データパック制作に関する課題】\
・predicateやNBTに関する知識と経験が足りていなかったため、複雑な処理や本来簡素化できた処理に時間をかけてしまった
